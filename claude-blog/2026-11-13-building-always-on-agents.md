## 重點摘要

1. **永遠在線代理大部分時間處於休眠狀態**：代理以短暫的「runs（執行）」為單位醒來處理事件，在一個 session 的對話記錄中完成工作並儲存狀態，不需要持續運行。

2. **事件收件箱（Event Inbox）是核心架構**：透過持久化表格、處理器與工作程序組成的事件收件箱，可防止競爭執行與事件遺失。建議只允許一個工作程序同時活躍，並以收件箱作為事實來源。

3. **計時器讓代理能主動行動**：後續追蹤可設為自訂截止日期，定期任務則設為週期性排程。獨立的排程器會輪詢計時器存儲，並將到期事件加入收件箱。

4. **記憶體與工作程序分離儲存**：長期記憶應保存在持久化儲存中，與工作程序解耦，包括使用者指令、筆記、過去訊息與任務進度等無法即時查詢的資訊。

5. **權限與輸出管理降低風險**：憑證透過代理程式處理，需人工確認的工具呼叫進入延遲佇列（outbox），代理應從安靜開始逐步獲取使用者信任。

## 重要公告

- 本文無新功能或產品發布，主要為架構最佳實踐指南。
- 文中引用 Opus 5.5 與 Opus 5 的基準測試數據：在長期程式碼任務上，Opus 5.5 每個解決任務的成本比 Opus 5 低 **78%**，顯示模型能力與成本效益的大幅改善。
- 文章提及 Claude Code 的自動模式（auto mode）及自動記憶（auto memory）等現有工具，以及 Messages API 的 memory tool。
