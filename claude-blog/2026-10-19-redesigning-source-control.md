## 文章資訊

- **發布日期**：2026-10-19
- **分類**：工程技術

## 重點摘要

1. **規模爆炸性成長導致瓶頸**：Anthropic 的程式碼合併量從 2026 年 5 月的每日約 2,500 次激增至 9 月的 3 萬次以上，主要由 AI 代理驅動。原有的 git 基礎設施為人工開發規模設計，無法應付如此高速的工作量，成為開發的主要瓶頸。

2. **git 在超大規模下的侷限**：主分支歷史紀錄接近 100 GB，壓縮後的工作目錄超過 25 GB。每日約 2,500 萬次 CI 檢出（checkout）需要數百台內部 git 鏡像伺服器，維運複雜度隨合併速度持續攀升。

3. **自建版本控制系統 Scion**：Anthropic 推出名為 Scion 的內部版本控制系統，核心設計假設客戶端（多為 AI 代理）始終在線，因此將歷史記錄、blame、合併、rebase 等操作全部移至伺服器端處理，客戶端僅保留有限的本地快取，所有元件均可水平擴展。

4. **顯著的效能改善**：採用 Scion 後，基礎設施的 CPU 與記憶體用量降低約 200 倍；CI 與研究用的程式碼檢出時間從數分鐘縮短至數秒；CI 整體也釋放出約 25% 的 CPU 容量。

5. **Claude 在建置過程中扮演關鍵角色**：七人團隊在五個月內完成了 Scion、內部程式碼審查工具 Antique 以及相關系統的開發。Claude 重寫了手工打造的資料注入管線，將記憶體使用量降低 20 倍、執行時間縮短 4 倍；工程師則專注於架構決策，並在代理過度設計時適時介入調整。

## 重要公告

- **Scion**：Anthropic 自建的版本控制系統，已取代 git 用於管理公司的單一程式碼倉庫（monorepo）。Anthropic 表示 Scion 非通用的 git 替代品，難以對外開放，但計畫與 GitHub、GitLab 及開源社群合作，推廣其核心設計理念（如伺服器端 RPC 與稀疏可組合的 git 功能）。
- **Antique**：與 Scion 同期開發的內部程式碼審查工具，支援語意式審核規則，可區分瑣碎變更與敏感修改。
- 文章揭示在開發期間，**Claude Mythos Preview** 與 **Claude Tag** 已可於內部使用，但並未宣布對外發布。
