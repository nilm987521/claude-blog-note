# 程式碼工作階段越來越長、使用更多上下文，Claude Opus 5.5 正是為此而生

**文章網址：** https://claude.com/blog/claude-opus-5-5-built-for-coding-sessions-that-use-more-context

## 重點摘要

1. **成本效益提升：** 對於典型工作負載，Claude Opus 5.5 的執行成本比 Opus 5 約低 40%；快取 token 讀取費用更比前代模型低 60%，對長時間程式碼工作階段的節省效果尤為顯著。

2. **改進的快取管理：** Claude Code 平台現在更有效地保留快取上下文，未命中快取的輸入減少超過 50%；同時支援一小時快取存留期以及子代理程序的快取繼承功能。

3. **更快的輸出速度：** Claude Opus 5.5 的輸出速度比 Opus 5 快超過 30%，並且完成相同任務所需的回合數更少。

4. **反映真實開發行為：** 數據顯示，過去六個月來，每次請求的上下文量增長了 2.6 倍，Claude 每個提示的工作時間延長了 3.3 倍，此模型正是針對這種現代代理程式碼工作流程而優化。

5. **節省效果複利疊加：** 成本降幅對長時間、高上下文依賴的工作階段效益最大，組織應透過維持一致的模型選擇和妥善管理快取存留期來最大化節省。

## 重要公告

- **新模型發布：** Claude Opus 5.5 正式推出，專為上下文密集的長時程式碼工作階段設計。
- **定價變動：** 相比 Opus 5，運行成本降低約 40%；快取 token 讀取費率降低 60%。
- **效能改進：** 輸出速度提升 30% 以上，並引入一小時快取存留期與子代理快取繼承機制。
